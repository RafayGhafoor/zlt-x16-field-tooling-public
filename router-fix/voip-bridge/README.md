# voip-bridge — browser call terminal for the ZLT X16

Two-way **VoLTE call audio in a browser**, inside QManager: a **card on the
dashboard** and a **Calls tab** with the full panel. Speak into the page's
microphone and the far end hears you; the far end comes back through the page's
speakers. Call control is the modem's own (`ATD` / `ATH`+`AT+CHUP` / `AT+CLCC`).

```text
Browser mic ──WebRTC/PCMU 8 kHz──▶ x16-webrtc ──UDP PCM──▶ x16-audio ──PCMIO──▶ alsa_daemon ──▶ VoLTE uplink
Browser spk ◀─WebRTC/PCMU 8 kHz── x16-webrtc ◀─UDP PCM── x16-audio ◀─output_cb── alsa_daemon ◀── VoLTE downlink
                                        └── /bin/atcmd: ATD / ATH / AT+CLCC
```

Full reasoning, measurements and failure modes: [`docs/27-call-terminal.md`](../../docs/27-call-terminal.md).

## Why it is not the X28 shape

The X28 bridges `arecord hw:0,12` / `aplay hw:0,0`. This ODU has no call-audio
ALSA device at all — card 0 is built from `msm-stub-*` and `snd-soc-dummy` — so
the only byte-level path to call audio is the vendor PCM tap:

```
libolinterface.so.1  Sunsea_Audio_PCMIO_Open / SendPcm / Close
    → /tmp/alsa_server_socket → alsa_daemon → agm_server → ADSP → modem voice
```

`x16-audio` turns that tap into two loopback UDP PCM streams. And because the tap
is 8 kHz mono, the bridge speaks **G.711 µ-law** — WebRTC's mandatory codec — so
there is no Opus, no cgo and no resampling: a pure-Go static ARMv7 binary.

## Payload

| File | Lands at | What |
|---|---|---|
| `bin/x16-audio` | `/data/webrtc/bin/` | PCMIO duplex pump (C, armhf, dlopens the vendor lib) |
| `bin/x16-webrtc` | `/data/webrtc/bin/` | WebRTC/PCMU bridge, call control, page, HTTPS proxy (Go, static) |
| `zlt-webrtc.sh` | `/data/webrtc/bin/` | cert, start/stop, status, `recover`, boot-hook plumbing |
| `zlt-webrtc.service` | `/etc/systemd/system/` | manual `systemctl restart zlt-webrtc` (not the boot path) |
| — | `/data/webrtc/etc/` | self-signed ECDSA P-256 certificate (generated by the bridge) |
| — | `/etc/initscripts/StartTZApp` | + one hook line; units under `/etc/systemd/system` get no boot job on this firmware |

Sources: `x16-audio.c`, `bridge/` (Go: `main.go`, `g711/`, `ca.go`, `certgen.go`,
`taplog.go`, `calllog.go`, `recorder.go`, `contacts.go`, `uplink_mixer.go`,
`cmd/smoketest`), `build.sh`.

## The QManager half (app-layer source)

The Calls page and the dashboard card are QManager **source**, not payload — and
the QManager tree they were written in is not a git repository. `qmanager/` holds
those files byte-for-byte with hashes, so a clean `QM_SRC` can be restored:

```
qmanager/overlay/…      33 files: app/cellular/calls/, components/cellular/calls/,
                        components/dashboard/calls-dialog.tsx, hooks/use-call-terminal.ts,
                        hooks/use-dial-keys.ts, types/calls.ts, lib/phone.ts, and the
                        nav/locale/shapes edits
qmanager/MANIFEST.sha256  hashes, built against QManager v0.1.18-draft
qmanager/apply.sh        --apply (default) | --check | --list, honours QM_SRC
```

```sh
cd router-fix/voip-bridge/qmanager
./apply.sh --check           # is this tree already carrying the feature?
QM_SRC=/path/to/qmanager ./apply.sh
```

The overlay replaces whole files, which is why `apply.sh` warns when the target
is not the version it was built against: re-run `bunx tsc --noEmit && bun run
build` and look at the diff before deploying.

## Build and deploy

```sh
./install.sh --build-only    # zig cc (C pump) + go build (bridge) -> bin/
./install.sh                 # push + certificate + unit + boot hook + verify
./install.sh --check         # verify only
./install.sh --uninstall     # stop, unwire, remove (cert and logs kept)
```

`ZLT_HOST` (default `zlt-root`, per `AGENTS.md`) and `ZLT_TRIES` are honoured. Build host
needs `zig` and `go`; the device needs nothing new.

## What it does beyond dialling

| Feature | Where it lives | Notes |
|---|---|---|
| Dialler | dashboard header → popup | phone icon (state dot on the icon) opens an animated dialler: number plate, 3×4 keypad, Call/Hang up/Mute (`M`); keyboard digits/Backspace/Enter work without field focus |
| Multi-device join | one cellular call, up to 4 browser peers | shared downlink track + per-peer 8 kHz RTP reorder buffers + one 20 ms PCM mixer; peers free after a 5 s ICE-disconnect grace |
| Call states | CLCC + bridge | dialing / ringing / **incoming** / active / held, plus **ended** for 8 s with the outcome |
| Answer / decline | `ATA` / verified `ATH`→`AT+CHUP` | incoming calls raise a banner on the dashboard; detection is the existing poller, one `AT+CLCC` per 5 s when idle |
| Mute | browser track | `track.enabled=false`: the call continues, only the mic goes silent |
| Call log | `/data/webrtc/log/calls.jsonl` | one line per finished call, 500 entries, direction from CLCC |
| Recordings | `/data/webrtc/recordings/*.wav` | stereo WAV per answered call: **L = far end, R = mixed browser mic (post-gain)**; keeps 50; native audio player and download in the Calls page |
| Contacts | `/data/webrtc/contacts.json` | vCard import (FN/N/ORG/TEL/EMAIL, folding-aware), matched on the last 9 digits |

## Certificates: a local CA, so the browser stops warning

`/data/webrtc/etc/ca.crt` is a local root CA (ECDSA P-256, CA:TRUE, 10 years);
`server.crt` is a 825-day leaf it signs for `IP:192.168.3.1, 127.0.0.1, localhost`.
The root is downloadable at `https://<device>:8444/ca.crt` — install it **once**
per phone/laptop and every page served here is trusted, no warning, microphone
allowed, and the leaf can be rotated for years without touching clients.

```sh
ssh zlt-x16-root '/data/webrtc/bin/zlt-webrtc.sh ca'   # path, URL, fingerprint, install steps
```

Let's Encrypt is not an option for a private address: HTTP-01 needs the internet
to reach the device, and DNS-01 needs control of a public zone (sslip.io/nip.io
give a hostname but not the zone). If the customer owns a domain and publishes a
record pointing at 192.168.3.1, drop that certificate and key in place with no
`ca.key` present and the bridge will keep it untouched.

## Three URLs, and why

| URL | What | Microphone |
|---|---|---|
| `https://192.168.3.1:8443/` | the bridge's own standalone page, no login | yes |
| `https://192.168.3.1:8444/cellular/calls/` | QManager proxied over HTTPS, `/callapi` on the same origin | yes |
| `http://192.168.3.1:8080/cellular/calls/` | the QManager tab directly | **no** — the page says so and links to :8444 |

`getUserMedia()` needs a secure context, and QManager's httpd has no TLS, so the
bridge terminates TLS itself and proxies QManager. Same-origin `/callapi` also
avoids CORS and avoids asking a browser to trust the device cert for a host it is
not on.

## Verify

```sh
ssh zlt-x16-root '/data/webrtc/bin/zlt-webrtc.sh status'    # process, listeners, cert, state JSON, hook
ssh zlt-x16-root '/data/webrtc/bin/zlt-webrtc.sh verify'    # exits non-zero unless every piece answers
cd bridge && go test ./...                                  # G.711 pinned against ffmpeg
cd bridge && go run ./cmd/smoketest -url https://192.168.3.1:8443 \
     -call <number> -seconds 20                             # headless browser stand-in
```

`cmd/smoketest` does exactly what the page does over the wire (offer, answer,
PCMU, tone) and prints downlink packets and peak RMS — the fastest way to tell a
device problem from a browser problem.

## Operating rules learned on this device

- **`ATH` can lie.** On this firmware an active VoLTE call can survive `ATH`
  (which still answers `OK`) while the far end stays connected; `AT+CHUP` is what
  actually ends it. The bridge tries `ATH`, re-reads `AT+CLCC`, then uses
  `AT+CHUP`, and logs which one worked. Never trust a hang-up without re-reading
  the call state.
- **Every AT command shares QManager's mutex.** `/bin/atcmd` is one global
  vendor request broker, no daemon-side timeout. The bridge uses the same
  `/tmp/qmanager_at.lock` flock as qcmd; a timed-out command quarantines the
  bridge rather than queuing further requests. If the broker itself is wedged,
  see docs/09-features.md's exact `start_atcmd_daemon` recovery — never restart
  TZApp, QCMAP or the dialer for this.
- **Quarantine never blocks hang-up, and it heals itself.** `ATH`, `AT+CHUP`,
  `ATA`, `AT+CHLD` are always sent; any reply lifts the quarantine; the poller
  probes with one `CLCC` every 15 s. If the modem cannot be read for ~6 s the
  state becomes `unknown` instead of staying `active`, and the tap stops being
  reopened — a finished call must not look answerable. `/api/hangup` returns
  `ok:false` plus the ATH/CHUP trace when the call really did not end.
- **Concurrent browser talkers do not share a UDP socket unframed.** Each peer is
  reordered/mixed to a fixed 20 ms frame before one datagram goes to the modem;
  the mixer caps four peers and drops stale queue samples instead of growing RAM.
- **Never `kill -9` the PCM pump during a call.** `alsa_daemon` keeps the dead
  client and then blocks every `PCMIO_Open`; only a daemon restart or a reboot
  clears it. Use `zlt-webrtc.sh stop` (SIGTERM → `PCMIO_Close`).
- If audio stops and the session card reports the tap never opened:
  `zlt-webrtc.sh recover` (restarts `alsa.service`; voice-only, refuses while a
  call is up; the data call is not touched).
- The tap is opened **only while a call is answered**. Without a call the vendor
  reader times out after ~3 s and writes start failing (`stop writing`) — that is
  normal, not a fault.
- The vendor library logs ~24 kB/s while a call is up. The supervisor filters it
  to the meaningful dozen and caps the file at 512 kB
  (`/data/log/x16-webrtc-audio.log`); the bridge's own log is
  `/data/log/x16-webrtc.log`.
- The certificate is minted by the bridge, not openssl: openssl 1.1.1 on this
  image duplicates `basicConstraints` and produces a CA cert with no EKU, which
  Go and macOS reject.

## Rollback

```sh
./install.sh --uninstall
# QManager half: restore the backed-up www
ssh zlt-x16-root 'tar xzf /data/zlt-backups/<date>/qmanager-www/www-pre-calls.tgz -C /data/qmanager/www'
```

`sunsea-pcm-probe.c` (with its armhf binary) is kept as the research probe that
recovered the ABI. It is not deployed.
